## 1. Summary

Built the pre-release website for the product — the four pages `phase-3-month-two.md` scoped for
Week 6, plus five more (signup, key page, support, contact, admin queue) the manual-payment flow
turned out to need. This ran nine weeks early and outside any scheduled track; nothing in
`services/signal-data` or the strategy split was touched.

Three things drove the actual shape of the work:

1. **There is no payment processor.** A buyer pays by UPI or in USDT, uploads a screenshot, and a
   human approves it — so `contracts.md` S5 (payment → key issuance via webhook) had to be
   re-read as "webhook, but the trigger is a person clicking Approve," not rewritten.
2. **The site had to exist before it could be shown to anyone.** The whole thing runs against a
   mock data layer (`apps/site/lib/mockApi.ts`) rather than `services/api`, which does not have
   these routes yet — same contract-first reasoning `contracts.md` already uses for S1–S3.
3. **A first attempt, in `apps/web` (the existing Vite scaffold), was abandoned mid-morning** in
   favour of a fresh Next.js app once the visual and motion requirements grew past what that
   stack was set up for. `apps/web` is reverted to its pre-session state in this commit; nothing
   of the abandoned attempt survives except this sentence.

## 2. What exists — `apps/site`

Next.js (App Router) + TypeScript, Tailwind v4, GSAP/ScrollTrigger + Lenis for scroll. Ten routes,
all static (`output: 'export'`), all verified served as plain files rather than only through
`next dev`:

`/` `/pricing` `/login` `/signup` `/checkout` `/key` `/policy` `/support` `/contact` `/admin`

**Palette matches the product, not an invented one.** Every colour token in
`apps/site/app/globals.css` is copied from `apps/desktop/src/ui/theme.css` — the desktop app's own
stylesheet — because the site is the front door to that window and the two should not look like
different products. First pass used an invented amber palette; caught and redone same day.

**The landing page runs claim → proof → application → terms**, fifteen sections, three of them
canvas sequences scrubbed to scroll position rather than revealed on entry:

- A candle compressing from ~280 individually-coloured trade marks, the colour draining out as
  they merge — the aggressor-side-is-lost argument, performed rather than asserted.
- Two panels sharing one candle geometry object (so they are identical by construction, not by
  luck) with opposite CVD lines scrubbing apart beneath them.
- Absorption: size stacking under a price line that stays flat, then the small red candle that
  gets drawn over it fading in.

One section — "what we are not claiming" — has no animation at all, on purpose; after five
scroll-driven sections a section that stops moving reads as dropping the sales voice, and the
comment in `NotClaiming.tsx` says not to "fix" that with a fade.

## 3. The pre-release gate

- A signed-out visitor sees a holding page at every route except `/login`, `/signup`, `/support`,
  `/contact`.
- **Any signed-in account** — not only an admin — gets past the gate. Pre-release access means
  "you were given a login," not "you are staff." `/admin` stays behind its own, separate role
  check.
- Two mock accounts exist for handing to reviewers: `admin@trading-intelligence.local` (also
  opens `/admin`) and `reviewer@trading-intelligence.local` (past the gate, nothing more). Both
  shown on the login page itself in mock mode.
- A short-lived `NEXT_PUBLIC_PREVIEW_PUBLIC` build flag that opened the site to anyone with the
  link (used for one early review copy) was removed once the two-account approach covered the
  same need more precisely — a flag that opens a pre-release site to the internet is a worse
  answer than an account, once an account is on offer at all.

## 4. Verification — what was actually run, not just written

- `pnpm build` clean, TypeScript clean, all ten routes prerendered, on every round of changes.
- Static export served with `serve` (not `next dev`) and driven with the browser tool: clean-URL
  routing on every route (`/pricing`, `/checkout`, … all 200), landing page scroll sequences
  scrubbed to real scroll position, pinned section behaviour, mobile at 390px.
- **Full purchase flow driven end to end**: signup → checkout (both UPI and USDT) → synthetic
  screenshot upload → admin approval → key issued. Issued key: `ti_live_` + exactly 32 chars,
  `tier: "core"` — matches `contracts.md` S3 on the first attempt.
- **Double-approval forced deliberately**: reset an approved payment back to `pending`, approved
  it again, confirmed one key still exists and the same key came back — S5's "webhooks arrive
  twice" idempotency rule, exercised against the human-approver version of that seam.
- **Two real bugs found this way, not by reading the diff:**
  - The reduced-motion still for the lossy-compression sequence rendered an almost-empty canvas
    (post-compression state) under a caption describing trades disappearing that a reduced-motion
    visitor never saw move. Fixed with a dedicated composite for that state; caption reworded to
    be true in both states.
  - The pinned "how it runs" section used `start: 'top 75%'`, which is correct for a scrubbed
    reveal but pins a *pinned* section a quarter-screen too early, stranding a screen and a half
    of dead space above it before the pin engages. `useScrubber` now takes an explicit `start`,
    defaulting to `top 75%` for reveals and set to `top top` for the one section that pins.
  - The pre-release banner read "you are seeing this because you are signed in" on `/login`
    itself for a signed-out visitor, because it was keyed on `!release.isPublic` alone rather
    than on whether *this* visitor had actually bypassed the gate. Fixed to key on
    `!release.isPublic && canSeeSite`.
- Deployed to Cloudflare (the user's own account, direct-upload of the static export) as a real
  review link for a non-technical teammate — confirmed working from a cleared-storage browser:
  holding page → sign in → real site, `/admin` correctly refused to the plain account.

  wallet address and chain, and the three founders' names and roles are all `PLACEHOLDER_…` in

  equivalents of the agreed USD prices, not numbers anyone signed off on.
- **The policy/refund page is a draft, marked as such on the page.** Not legally reviewed. The
  SEBI research-analyst question flagged elsewhere in this repo is still open and decides whether
  the site may use words like "signal" at all — do not take a real payment against this page
  before that call happens.

  and Chrome at a 390px viewport were checked.
