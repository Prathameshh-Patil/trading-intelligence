## 3. Rebase conflict — extension architecture, not a mechanical conflict

`origin/main`'s copy of `apps/extension` was still the **popup** implementation from Day 1;
the side-panel rewrite (`SidePanel.tsx`, `background.ts`, `views/`, etc.) had only ever existed
locally, uncommitted. Rebasing `b30cee9` onto `origin/main` produced real conflicts in
`vite.config.ts`, `public/manifest.json`, and the retired `App.tsx`/`App.css` — not because two
people edited the same line, but because the two branches represented two different, both-valid
architectures for the same problem (popup vs. side panel). Resolved by keeping the side-panel
functionality throughout, but merging forward two things from the popup's manifest that were
still correct and had simply gone missing from the rewrite: the `icons` block and
`browser_specific_settings` (Firefox support).

## 4. Extension build — broken by the sync, then fixed

### The break

Pulling `b30cee9` broke `pnpm build` for `apps/extension` with
`[UNRESOLVED_ENTRY] Cannot resolve entry module src/content/main.ts`. Two separate problems:

1. `src/content/main.ts` did not exist anywhere in the working tree or in either branch's
   history — genuinely lost, not misplaced. `vite.config.ts` and `manifest.json` both still
   referenced it as if it did.
2. `manifest.json`'s merged `content_scripts` block matched `<all_urls>` — a standing
   permission to read every page the user visits. `8cd4790` (21 Aug) had deliberately removed
   exactly this for the popup, for exactly this reason: it draws Web Store review scrutiny for
   no real benefit when `activeTab` gets the same result on-demand.

### The fix

Rather than reconstructing the lost file and keeping `<all_urls>`, `capture.ts` was rewritten
to use the same `activeTab` + `chrome.scripting.executeScript` pattern `8cd4790` already
proved out for the popup: the selection is read from the active tab only at the moment the
user clicks "Capture screen" inside the side panel (a qualifying user gesture for `activeTab`).
`vite.config.ts` dropped the `content` build entry; `manifest.json` dropped `content_scripts`
and the now-unused `tabs` permission, keeping `activeTab`, `scripting`, `storage`, `sidePanel`.

A second, unrelated bug found while reviewing this: `AnalyzeView.tsx` sent `capture.text`
to the backend unconditionally, including when a capture was screenshot-only (empty text). The
backend requires non-empty text (`min_length=1`), so that request always 422'd, and the
resulting error was indistinguishable from the service actually being down. Fixed to skip the
network call entirely when there's no text, with an honest "no text was captured" message
instead.

`_to_delete/` (scaffold leftovers, including a 42KB `.tgz`) had also been committed in both
`apps/extension` and `apps/desktop`. Untracked from both and added to the root `.gitignore`.

pnpm workspace. `SidePanel.tsx`, `lib/`, `ui/`, `views/` copied byte-for-byte from
