## 1. Summary

**The Dukascopy block has changed shape, and the pull could never have converged even without it.**
Two separate facts, and the second is the one worth having:

1. The endpoint is **not** returning 503 to everything any more. Three cold probes returned real

2. **`spot.py` resumed by day, so a throttled pass discarded every hour it won.** With a request

The fix is four lines of moved logic and it is on `main` as `4772da6` —
`spot.py` now caches by hour. **No spot data has been pulled.** The budget is still far under a day.

**And the recovery measurement, which arrived late, is the one that decides it: the block has not
cleared in 13½ hours.** ~17 requests per budget against a recovery longer than half a day is
**~17 hour-files a day**; three months is 2,208 of them. **That is ~130 days, and it ends the
argument** — this address cannot bulk-pull this feed, and no amount of fixing `spot.py` changes it.

## 3. The defect the measurement exposed

`pull()` looped 24 hours into a list and wrote the day only if none was lost:

```python
if lost:
    continue          # the 14 hours that DID land are dropped on the floor
```

The resume granularity (a day) was coarser than the throttle budget (~17 requests). Every pass
therefore burned its whole budget, discarded the result, and left the next pass exactly where the
last one started. **Re-running it forever would have produced nothing**, which is a different
failure from "the pull is slow" and would have been read as the block never clearing.

**Fixed by caching each hour as it lands**, under `data/spot/XAUUSD/.hours/YYYY-MM-DD/HH.parquet`.
The invariant that motivated the day-level check is untouched: the day parquet is still written
only when all 24 hours are present, so **no day with holes ever reaches disk** and `atr_bp` /
`rv_slope` still cannot read an absent hour as a calm one. The hour cache is scratch and is deleted
once its day is assembled.

**Verification:**

- **2 new tests, 330 passing** (was 328), `ruff` and `mypy` clean.
- **The mutation fails.** Disabling the cache lookup (`if False and hf.exists()`) turns the new
  test red; reverting turns it green. The test asserts the second pass fetches *exactly* hours
  10–23 — the fourteen the first pass lost — and not the ten it already had.
- No test touches the network, per `test_spot.py`'s standing rule.

## 8. Later the same day — the room chose MT5, and the desk check changes what it is worth

Varad picked option (1). **Checked it against the documentation before any signup**, on the grounds
that the signup is the expensive step and two of its assumptions were load-bearing and untested.
Full writeup: [`SPOT_FEED_CHECK.md`](../services/signal-data/analysis/SPOT_FEED_CHECK.md) §7.
⚠️ **Nothing was run — no account, no terminal, no ticks.** These are sourced documentation claims,
not measurements, and §7 says so in its own first line.

**The Windows-only objection is real and does not reach the export.** The official `MetaTrader5`
Python package needs the Windows terminal, and row B already records that there is no Windows or
Linux machine in the loop — so the *API* is out without a Wine or Docker-QEMU bridge. But an
**MQL5 script runs inside the terminal**, which has a macOS build, and `CopyTicksRange` writes CSV
with a date range. The `Historex` script already does it. **So option (1) survives its first
objection**, and the daily-update line above that called it simply "free" was too generous: it is
free *via the script path only*.

⛔ **The depth finding, which does resize the prize.** Real tick history is served by the broker and
is **commonly 1–3 months**. **Nineteen months should be assumed unavailable** until a named broker
proves otherwise — so MT5 is a plausible **3-month** source and not a 19-month one. That is not
fatal: 3 months is the smaller target already in the plan, and a single dated export satisfies it
outright — no throttle, no ~130 days, no resume bookkeeping. **It is a real downgrade from what §6
implied when it recommended (1), and it is better to know it now than after a signup.**

⚠️ **And the trap worth the whole desk check.** MT5's Strategy Tester documents generating ticks
from an M1 bar **with a fixed spread inside the bar** when tick data is missing. Route 2 asks
exactly one question — *does spot bid/ask spread vary enough to filter on* — so a generated tick
does not add noise, it **answers the question by construction and answers it wrongly**: a fixed
intra-bar spread reads as degenerate, which is the null we are trying to test. **A study fed
generated ticks would conclude "spot spread is degenerate" and would be measuring MetaQuotes'
interpolation.** Same shape as an absent hour reading as a calm one, and it earns the same
treatment — made impossible rather than remembered.

⚠️ **One thing is deliberately left open.** Tick generation is documented as **Strategy Tester**
behaviour; whether a terminal-side `CopyTicksRange` export can also contain synthesized ticks is
**not established**, and asserting it either way from the docs would be inventing a finding. It
does not need a ruling — `MqlTick.flags` settles it per tick, which is why the acceptance test
below is written around that column rather than around a belief about the platform.

**The acceptance test, and none of it costs a signup until step 3:**

1. **Name the broker and read the depth first** — the Symbols panel (`Ctrl+U`) reports available
   tick history per symbol. A broker that will not serve 3 months of real XAUUSD ticks ends this
   route before an account exists.
2. **Export through `CopyTicksRange`, keeping `flags`.** Not the GUI: the MQL5 forum reports the
   `Flags` column missing from GUI-exported tick CSV, and an export without it cannot be audited.
3. **A loader must reject an export with no `flags` column outright** — a hard failure, not a
   warning — and must not average a spread over ticks that never moved a quote.

**Not built, deliberately.** No MT5 loader was written. The frame contract it would have to meet is
`decode_bi5`'s (`timestamp`, `bid`, `ask`, and the two volume columns that spot does not have and
A2 already established it never will), and writing a parser against a format nobody in this repo
has yet seen a byte of would be the speculative half of the work. **It waits for step 1's answer**,
which is a five-minute check in a terminal and decides whether any of it is worth writing.
