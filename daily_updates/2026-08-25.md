## What changed

### `app/analysis.py` — rewritten

The Day 1 lexicon is deleted. `analyze(text)` now makes one `client.messages.parse` call
to `claude-haiku-4-5` with a system prompt that defines each of the four fields, and
decodes the reply through a Pydantic `Analysis` model via structured outputs.

Structured outputs rather than forced tool use: same guarantee that the shape is
enforced, but no tool-call round trip and no manual `json.loads`, so it is meaningfully
less code for an identical result. `parsed_output` is `Analysis | None` — `None` means
the model refused or ran out of output tokens mid-object, so that raises rather than
returning a half-answer.

The four keys are unchanged. That was the whole design of the Day 1 baseline and it held:
no extension change, no contract change, no migration.

### `app/api/routes/analyze.py` — a `503` path

`anthropic.APIError` (service down, rate limit, bad key) and a schema-failing answer both
become `503 {"status": "error", "analysis": "unavailable", "error": "..."}`. This mirrors
the shape `/api/v1/health/db` already returns, so the API has one way of saying "the thing
behind me is not answering" rather than two.

`ValidationError` subclasses `ValueError`, so one `except (anthropic.APIError, ValueError)`
covers both. The function it wraps is five lines, so the catch is narrow in practice.

Checked the extension before adding this: `apps/extension/src/lib/api.ts` renders any
non-200 as `The analysis service returned ${status}` and never reads `detail`, so a
dict-shaped detail cannot break it. No extension change needed.

### `app/config.py`, `.env.example` (both) — the key

`anthropic_api_key: str`, required, no default — identical treatment to `database_url`.
A missing key is a startup failure with a clear pydantic error, not a surprise at the
first request. Documented in `services/api/.env.example` and the repo README, including
the point that tests only need the key to be *present*, not valid.

### `tests/test_api.py` — restructured

The old `test_bullish_text` / `test_bearish_text` / `test_neutral_text` /
`test_negation_flips_sentiment` asserted real lexicon behaviour. Against a network call
they would be slow, flaky and billable; against a stub they would be asserting that a stub
returns what the stub was given. Neither is worth having, so they were split:

- **13 boundary tests** stub `run_analysis` via `monkeypatch` and cover what actually
  breaks silently: response shape, whitespace stripping, the three validation rejections,
  the `503`, and CORS across Chrome/Firefox/localhost plus a foreign origin.
- **5 live tests** (bullish, bearish, neutral, negation, confidence/signal bounds) make
  real calls and skip unless `LIVE_API_TESTS=1`. A normal `uv run pytest` spends nothing.

Four more were added later in the day — see the verification section, which is where the
weakness in this split showed up: stubbing `run_analysis` meant `analysis.py` itself was
never executed by any test. Final count 17 (+5 skipped).

## Going back to verify — and the defect it caught

Went back to actually verify rather than trust the green suite, by driving `analyze()`
against a faked Anthropic transport (`httpx2.MockTransport`) so the real request building
and decoding ran. Four cases; two of them failed in a way that mattered.

**The defect.** `Analysis` was validating the *system prompt's style* as if it were the
contract: `confidence` bounded to 50–95, `signals` to at most 4. Dumping the schema the SDK
actually sends showed why that is wrong — numeric bounds and list maximums are stripped and
reappear only as a description string:

```
"confidence": {"type": "number", "description": "{maximum: 95, minimum: 50}"}
```

So the model is *asked* for 50–95, not constrained to it. And because `messages.parse`
validates client-side on the way back, any bound placed there becomes a hard error rather
than a correction. A model answering `confidence: 97` — a perfectly usable analysis —
raised `ValidationError`, which my own route then dutifully turned into a `503 analysis
unavailable`. Same for a 5th signal. Two spurious user-facing failure modes, both invented
by me, neither visible to `ruff`, `mypy`, or 13 passing tests.

Fixed by writing `Analysis` to the contract rather than the prompt: `confidence` 0–100,
`signals` non-empty. The prompt still asks for 50–95 and 1–4. Genuinely unusable output
(truncated JSON, refusal) still fails, which is correct.

| Model returns | Before | After |
| :--- | :--- | :--- |
| well-formed reply | 200 | 200 |
| `confidence: 97` | **503** | 200 |
| 6 signals | **503** | 200 |
| truncated JSON | 503 | 503 |

This is the second real defect verification caught, after the mypy `None` one. Both were in
code that type-checked and tested clean.

**The failure path is now verified against the real API.** A live call with the placeholder
key reached `api.anthropic.com` and came back `AuthenticationError` (401) — an `APIError`
subclass, so the route's `503` mapping is confirmed against the real service rather than a
mock of it. Costs nothing, since a rejected request is not billed.

## Later — the twelve-week execution path, split three ways

Source: the **Twelve Weeks to Ten Subscribers** artifact (shared, read 25 Aug). It says what to

**Two architectural facts from the artifact now constrain everything in this repo:**

- **A screenshot can never contain delta.** Delta needs the aggressor side of every individual
  trade; a rendered candle discarded that when it was drawn. Two sessions with identical candles
  can have opposite CVD. Capture stays, demoted to *context only* — symbol, timeframe, drawn levels.
  Every number comes from the feed. This is enforced as a type (`CaptureContext` carries no numeric
  field but `levels` and `confidence`) rather than as a convention, because it is exactly the
  mistake that becomes tempting in week eight.
- **Bring-your-own-feed.** The user connects their own CME entitlement, the overlay computes delta
  on their machine, no market data touches our servers. Databento's external distribution rights
  start at $1,750/mo, not the $199 tier; CME wants a separate five-figure derived-data licence on
  top. Deleting that one hop deletes the whole licensing bill. The cost is a narrower launch
  audience — futures traders on GC and NQ, not anyone with MT5.

web pages), with a deliberate frontend→backend ramp: Week 5 he consumes an API contract he did not

## Decision — the analysis backend is our own model

Closed late on 25 Aug, and it closes it differently from every option weighed earlier today.

None of Anthropic credit, Ollama or the Gemini free tier is taken. **We build our own model, and
the analysis work is parked until it exists.** No money goes on any account.

**Claude stays in `analyze()` as the interim implementation.** Removing it now would buy an empty
route and delete working, typechecked, tested code, which is the wrong trade. It returns
`503 analysis unavailable` on every call because the account has no credit — the correct behaviour
for an unreachable upstream, and the one thing this leaves genuinely usable is the error path.

**The four-key contract is what makes this survivable.** `sentiment` / `confidence` / `summary` /
`signals` stay frozen, so the own model drops in behind the same `analyze()` signature with no
route, no contract and no extension change. That seam has already been swapped once under load —
lexicon → Claude on Day 3, zero extension edits — so this is a repeat of a move that worked, not a
hope. Day 1's decision to freeze that contract has now paid for itself twice.
