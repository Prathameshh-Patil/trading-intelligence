## 2. What was measured, and the controls that make it a finding rather than a guess

Three probes against `2025-06-18 14/15/16h` — the exact hour verified on 7 Sep and again on the
evening of 9 Sep, so a failure there is the endpoint and not a missing file:

```
probe 14h  ConnectionError: HTTP Error 503
probe 15h  ConnectionError: read operation timed out
probe 16h  ConnectionError: HTTP Error 503
0/3
```

Then the same URL under widening conditions, to separate "our client is wrong" from "we are
blocked":

| | |
| :--- | :--- |
| `UA` + `Accept` (what the module sends) | timeout |
| full browser headers — `Accept-Language`, `Referer`, `Origin` | connection reset |
| **a different instrument**, `EURUSD` | connection reset |
| `curl` rather than `urllib` | 503 |

And the controls, same second: **`example.com` 200** and **`www.dukascopy.com` 200**. The network
is fine and the host answers; only `datafeed.dukascopy.com` refuses.

**So this is not the `User-Agent` problem `SPOT_FEED_CHECK.md` §2 diagnosed, and not the missing
`Accept` header fixed in `6358d85`.** Both of those were client bugs with a clean fix. This is an
IP-level block on the data endpoint, tripped by roughly 40–60 requests in one evening, and it
outlasts a day.

## 3. The claim this corrects

`SPOT_FEED_CHECK.md` §1 said: *"The feed works. XAUUSD tick history is free, complete and decodable,
and the spread is not degenerate."* Every word of that is still true, and it was **measured on one
hour**.

**"Usable as a backtest source" was never tested, and it does not survive.** Three months is ~2,200
hour-files; 19 months is ~13,900. This endpoint tolerates neither from one address. The doc now
carries that amendment at the top of its verdict rather than as a footnote, because the difference
between "free" and "free and bulk-pullable" is the whole question for a vendor decision.

**Nothing in it is retracted.** The spread distribution, the quote rate and the decoder are all
still good; `dukascopy.py` is still correct. What changed is what the result licenses.

---

## 4. What was not done, deliberately

**No further pulling.** Two probe rounds and one control round, spaced, then stopped. Grinding an
endpoint that is already refusing is how a block stops being temporary, and there is no result on
the other side of it worth that.

**No attempt to get around the block.** Running the same pull from another address would probably
work and is not a decision for a session at 2am — it changes the question from "is this feed usable"
to "is this feed usable if we work around its limits", which is exactly the kind of thing the room
should answer with the vendor decision it already owns.
